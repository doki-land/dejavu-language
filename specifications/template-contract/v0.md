# Dejavu 模板契约 v0

状态： **v0 核心表面已冻结**（2026-08-11）。本文件是宿主无关规范，不是某个包或下游产品的发布说明。

下方所列的可观察解析、渲染和 loader 行为，对所有声明兼容的宿主锁定。后续版本可以增加能力，但不得静默改变已冻结语义。

| 层   | 版本    | 含义                                |
|------|---------|-------------------------------------|
| 契约 | **v0** | T1 + 继承 + 过滤器 + path-v1 loader |

宿主实现是否已经通过共享夹具，不由本文件宣称；请查看各宿主的兼容性状态和具体 conformance 输出。

## 目标

一份版本化的解析、渲染和 loader 契约。实现可以不同，可观察行为不得不同。正式执行路径消费本文件定义的 IR，不使用 legacy AST。`IrDocument` 以 `irVersion: "v0"` 携带合同身份；实现必须显式拒绝未知或缺失的 `irVersion`，不得回退解析。

### v0 范围

| 纳入 v0（已冻结）                          | 延后（后续版本）              |
|--------------------------------------------|-------------------------------|
| T1 核心 + `\|>` 过滤器                     | macro / call                  |
| 继承：extends / block / super / include    | prepend / append 块           |
| path-v1 loader 解析                        | 异步 / FS watcher loader      |
| `strictUndefined`、SafeHtml `safe`/`raw`   | 上下文敏感转义                |
| Conformance：`t1`、`values`、`loader`、`inheritance`、`whitespace`、`include-context`、`partial-params` |                               |
| `IrDocument.irVersion` = `"v0"`，未知版本显式拒绝 |                             |

## T1 核心（稳定）

- 文本、注释、插值
- `if` / `else if` / `else` / `end if`
- `loop item in xs` / `end loop`
- 循环元数据：body 每次迭代隐式绑定 `forloop`（`index` / `index0` / `first` / `last` / `length` / `depth`），
  嵌套遮蔽与恢复、`depth` 入口规则与空数组语义见 `specifications/ir/v0/nodes.md` `Stmt.For`
- `break` / `continue`：绑定词法上最近的外层 `loop`（同一词法单元内：模板顶层、
  macro body、caller 块、partial body、block body 各为一个单元），越界为解析错误
  `dejavu.parse.control-outside-loop`；AOT 与 JIT 控制流一致，语义见 `nodes.md` `Stmt.Break` / `Stmt.Continue`
- 表达式：字面量（字符串 / 数字 / 布尔 / `null` / 对象）、标识符、成员/下标、二元/一元、`|>` 过滤器（单独的 `|` **不是**管道）
- 对象字面量：`{ key: expr, "key": expr }`，key 唯一，重复 key 为解析错误；求值得到普通对象
- 插值默认 HTML 转义；可通过 `|> safe` / `|> raw`，或宿主 `markSafe(...)` 退出转义

## 继承表面

| 语句    | 形式                         | 说明                                     |
|---------|------------------------------|------------------------------------------|
| extends | `extends <string-expr>`      | 子模板非 block 内容丢弃                  |
| block   | `block <name>` … `end block` | 覆盖槽位                                 |
| super   | `super`                      | 父 block 体；仅可出现在覆盖中的 block 内 |
| include | `include <string-expr> [with <expr>] [only \| without context]` | 默认继承上下文；检测环 |

### include 上下文

| 形式                                      | 子模板可见上下文                     |
|-------------------------------------------|--------------------------------------|
| `include path`                            | 调用方上下文                         |
| `include path with expr`                  | 调用方上下文 + `expr` 的条目（覆盖） |
| `include path only` / `without context`   | 空上下文                             |
| `include path with expr only`             | 仅 `expr` 的条目                     |

- `expr` 必须是对象或 `null`（`null` 等同于无显式条目）；其他值 → 诊断 `dejavu.template.context-not-object`。
- 子模板的变量写入不回流调用方上下文。
- include 目标仍必须由 catalog 解析；AOT catalog 模式只接受路径字面量。

### 参数化 partial

```
<% partial title, suffix = "!" %> … <% end partial %>
```

| 规则 | 说明 |
|------|------|
| 声明位置 | 一个模板最多一个 `partial`，且必须包住整个模板；其外层只允许注释与空白文本 |
| 嵌套 | `partial` 不得出现在 `if` / `loop` / `block` / 另一个 `partial` 内 |
| 参数 | 至少一个标识符参数；重复参数为解析错误 |
| 默认值 | `name = <literal>`，默认值只能是字面量；非字面量为解析错误 |
| 调用 | 仍用 `include <path> [with <object>]`，参数名即 `with` 对象的键 |
| 上下文 | 参数化 partial 不继承调用方上下文，只可见已绑定参数 |
| 必填缺失 | 诊断 `dejavu.template.missing-parameter` |
| 未知参数 | 诊断 `dejavu.template.unknown-parameter` |

`only` / `without context` 对参数化 partial 不再有额外效果，因为它本来就不继承调用方上下文。

## 宏与 caller 块

```
<% macro name(a, b = "x") %> … <% end macro %>
<% call(label, n) name(args) %> … <% end call %>
```

| 规则 | 说明 |
|------|------|
| 宏参数 | 与 partial 同一规则：标识符、重复拒绝、默认值仅字面量 |
| `call` 目标 | 只接受本模块声明或 `from ... import` 导入的宏，形如 `<% call(name(args)) %>` |
| caller 形参 | `call(a, b)` 中只能是裸标识符，不允许默认值，`caller` 为保留名；`call() name()` 合法（零形参） |
| 块作用域 | 块体在该 `call` 所在模板的作用域渲染，可见调用方全部上下文；形参覆盖同名项 |
| 重复渲染 | 宏内每次 `caller(...)` 都重新求值块体；绑定不泄漏到块外 |
| 不可用 | 宏未经 `call` 调用时使用 `caller()` → `dejavu.template.caller-unavailable` |
| arity | 实参数 ≠ 形参数 → `dejavu.template.caller-arity`，`args` 为 `got` / `maxArgs`，在 render 期报告（同一宏可被不同形参的 `call` 调用） |

`caller` 块是纯同步渲染，不引入异步、缓存或隐式上下文捕获；AOT 与 JIT 都在渲染期校验 arity，不做编译期特化。

需要 **path-v1** `TemplateLoader`（多根目录 catalog，或经 `MapTemplateLoader` 退化的单根 `map:`）。宿主不得叠加登记 bare /
`.html` 重复别名。

## Loader 与解析（path-v1）

能力标识：`loader.resolution = "path-v1"`（类型侧常量 `LOADER_RESOLUTION_PATH_V1`）。

本章对宿主与引擎均为规范性条文。类名非规范。

### 分层

| 层      | 职责                                                            |
|---------|-----------------------------------------------------------------|
| Catalog | 具名根 + 相对路径 → 源码/IR                                     |
| Resolve | 纯函数：`(ref, from?) → { root, path } \| Diagnostic`（不解析） |
| Load    | Canonical id → 解析/缓存 → `IrDocument`                         |
| Render  | 环检测 / 依赖 **只**使用 CanonicalId；从不使用原始 ref          |

### Canonical id

格式：`{rootName}:{posixRelPath}`

示例：`project:layout.html`、`theme:partials/a.html`、`map:child.dejavu`。

- `rootName` 对应 catalog 某一根的 `name`。
- `posixRelPath` 已规范化（`\` → `/`，无前导 `/`，无 `.` 段，无空段）。
- 路径是扩展名探测后的 **具体文件键**（例如裸名 `layout` → `layout.html`）。

### Ref 分类

trim 且 `\` → `/` 之后：

1. **scheme** — `^([A-Za-z][A-Za-z0-9_+-]*):(.*)$` → scheme + path（path 为空仅视为非法）。
2. **relative** — 以 `./` 或 `../` 开头。
3. **bare** — 其余一切（含 `layout.html`、`partials/x`）。

空 ref → 诊断 `invalid_ref`。

### 解析算法

```
normalize(ref) → raw
if raw empty → invalid_ref

classify(raw):
  scheme → lookup root by scheme
           if unknown → unknown_scheme
           probe(root, path) → hit | template_not_found
  relative →
           if from missing → relative_without_from
           parse from as CanonicalId (root + path)
           if from not canonical → invalid_ref (relative needs canonical from)
           join(dirname(from.path), raw) within root
           if escape → relative_escape_root
           probe(from.root, joined) → hit | template_not_found
  bare →
           for root in roots ordered by priority desc:
             probe(root, raw) → if hit return
           template_not_found (include searched root names)

probe(root, path):
  normalize path (escape → fail as relative_escape_root or not_found)
  if path already ends with a configured non-empty extension:
    candidates = [path]
  else:
    candidates = [path + ext for ext in extensions]  // 默认："", .html, .dejavu
  return first candidate present in root.files
```

### 覆盖与 scheme

- Bare 搜索： **更高 `priority` 优先**（按降序取首个命中）。
- Scheme 引用（`theme:layout`） **只**搜该根；priority 不适用。
- 宿主可以配置 root priority；同名 bare 引用由优先级更高的 root 命中。

### 诊断

实现抛出的错误须携带 `.diagnostic: TemplateDiagnostic`。`code` 为稳定机器码（不随 locale 变）。

| 码                      | 何时触发                                 |
|-------------------------|------------------------------------------|
| `invalid_ref`           | 空 ref；相对路径的 `from` 非 CanonicalId |
| `unknown_scheme`        | scheme 未绑定到任何根                    |
| `relative_without_from` | `./` / `../` 但缺少 `from`               |
| `relative_escape_root`  | `..` 逃出根                              |
| `template_not_found`    | 无候选                                   |

字段：`message` 必填；须含 `ref`；相对解析失败时带 `from`；bare/`scheme` 未命中时宜带 `searched`（已搜索根名）。

### 渲染边界

- `extends` / `include` 经 `loader.resolve(ref, { from })` 解析，其中 `from` 为当前模板的 **CanonicalId**。
- 访问栈 / include 栈只存 CanonicalId。
- 渲染期间每次成功 resolve 都调用 `RenderOptions.onDependency?.(canonicalId)`（供增量 / 构建图）。以具名模板渲染时，入口模板
  id 也应在渲染开始时报告一次。

### 宿主规则

- **不要**把同一内容同时登记为 bare 与 `.html` 别名。
- 在正确根下用真实相对路径登记一次（如 `layout.html`）。
- 单根测试可用根名 `map`（`MapTemplateLoader`）。

### Conformance

- `specifications/conformance/loader/` — 解析用例（priority、scheme、relative、escape、extension、missing）。
- `specifications/conformance/inheritance/` — extends/block/super/include（假定 path-v1 或 map 退化）。

## 定界符

`Language.template` 配置 `codeStart` / `codeEnd` / `commentStart` / `commentEnd`。默认：`<%` `%>` `<#` `#>`
。宿主可以配置其他定界符，但不能改变语义。

## 空白控制（P1，作者可见）

tag 两侧各有一个空白 marker。**左侧 marker** 写在开符号之后（`<%_` / `<%-` / `<%~` / `<%=`），
**右侧 marker** 写在闭符号之前（`_%>` / `-%>` / `~%>` / `=%>`）。层级是单侧可剥离宽度的阶梯：

| 级别    | marker | 剥离内容                                          |
|---------|--------|---------------------------------------------------|
| `none`  | `.`    | 不剥离（默认，无 marker 即此级别）                |
| `ws`    | `_`    | 水平空白（空格 / 制表符）                         |
| `nl`    | `-`    | 恰好一个换行（`\r\n` / `\n` / `\r`）              |
| `ws_nl` | `~`    | 水平空白、一个换行、再一段水平空白                |
| `all`   | `=`    | 连续的全部空白（含换行，Unicode 空白）            |

- 左侧 marker 剥离**前面** Text 的尾侧；右侧 marker 剥离**后面** Text 的首侧。
- IR 只在节点自身记录左侧级别（`trim` 字段）。右侧级别在解析阶段直接作用到后续 `Text`，
  因此 IR 消费者只需处理左侧。宿主与 AOT 生成器必须走同一份 `trim::normalized_children`，
  不得各自实现剥离。
- 复合语句的开 tag 右侧 marker 作用于 body 首个 Text；`extends` 只允许左侧。
- `else` / `else if` / `end if` / `end loop` / `end block` 等 closer 上**禁止** marker，
  出现即为 parse 诊断。
- `<%!` 转义形式的插值（输出字面 `<%`）不参与空白控制。
- 空白控制只改变文本，不改变上下文、循环作用域或继承语义。

## 值模型（P0）

值模型是宿主无关合同。宿主不得以本语言的类型强制转换（JavaScript / Rust / Python / C# 原生 coercion）
替代下表规则。

### truthiness

| 值                | truthy |
|-------------------|--------|
| `null` / missing  | false  |
| `false`           | false  |
| `true`            | true   |
| 数字 `0`          | false  |
| 非零数字          | true   |
| 空字符串 `""`     | false  |
| 非空字符串        | true（含 `"0"`、`"false"`） |
| 空数组 / 空对象   | false  |
| 非空数组 / 对象   | true   |

### 比较与运算符

| 表达式      | 规则                                                          |
|-------------|---------------------------------------------------------------|
| `==` / `!=` | 结构相等，**不**做跨类型转换（`1 == "1"` 为 false）           |
| `<` `<=` `>` `>=` | 仅两侧都是 number 时比较，否则结果为 `false`           |
| `&&` / `||` | 两侧按 truthiness 求值，结果恒为 boolean                     |
| `in`        | 数组：成员相等；字符串：左值字符串化后为子串；对象：字符串化后为 key；其他为 `false` |
| `+`         | 两侧都是 number 才相加，否则两侧字符串化后拼接                |
| `-` `*` `/` `%` | 仅两侧都是 number，否则 `null`；结果非有限 → `null`       |
| 一元 `-`    | 仅 number，否则 `null`；一元 `+` 为恒等                       |

字符串化：`null` → `""`，`true`/`false` → `"true"`/`"false"`，number 按 JS `String(n)`
（整数值不带 `.0`），数组/对象为紧凑 JSON。

### undefined 与 strict

缺失标识符、缺失成员、缺失下标 → `null` → 插值为空字符串（不是字面量 `undefined`）。
`RenderOptions.strictUndefined: true` 时缺失标识符抛 `UNDEFINED_VARIABLE`。
`null` 与「缺失」在值层面等价，filter 也不能区分两者。

## 过滤器（P0 内置）

`uppercase`/`upper`、`lowercase`/`lower`、`trim`、`default`、`length`、`join`、`replace`、
`escape`/`e`、`safe`/`raw`、`date`（`%Y %m %d %H %M %S`）、`slug`。

参数形式：`value |> filter(arg)` 或 `value |> filter: arg`（冒号形式）。

| filter                   | 规则                                                                |
|--------------------------|---------------------------------------------------------------------|
| `uppercase` / `lowercase` / `trim` | 先字符串化再转换                                          |
| `default(fallback)`      | 仅 `null` 与 `""` 视为缺失；`0`、`false`、空数组、空对象**不**替换  |
| `length`                 | 字符串按 Unicode code point 计数，数组按元素，对象按 key，其他为 `0` |
| `join(sep=",")`          | 数组逐元素字符串化后拼接；非数组为该值字符串化                      |
| `replace(from, to)`      | 全部替换                                                            |
| `escape` / `e`           | 内部已 HTML 转义，渲染时不再二次转义                                |
| `safe` / `raw`           | 原值返回并跳过自动转义                                              |
| `date(pattern)`          | 默认 `%Y-%m-%d`；最小 strftime：`%Y %m %d %H %M %S %%`；UTC；无法解析 → 空串 |
| `slug`                   | NFKD → 去组合符 → 小写 → 非 `[a-z0-9]` 折叠为 `-` → 去首尾 `-`      |

### 过滤器 registry 与 capability

过滤器集合是**语言中立的静态描述**，不是宿主各自硬编码的名单。每个条目包含
`name`、`aliases`、`minArgs`、`maxArgs` 与 `capability`（`pure` 或 `safe-output`）。

| 宿主 | 消费方式 |
|------|----------|
| Rust JIT（`dejavu-ir`） | 渲染前按 registry 校验名称与参数个数 |
| Rust AOT（`dejavu-codegen`） | 编译期按 registry 校验，未知过滤器/参数个数违约产生编译诊断 |
| TypeScript AOT（`dejavu-engine/runtime`） | 运行时按同一描述校验并抛结构化错误 |
| 一致性门 | `pnpm conformance` 先对比 Rust dump 与 TS 表，要求逐项一致 |

未知过滤器 → `dejavu.template.unknown-filter`；参数个数违约 → `dejavu.template.filter-arity`。
`capability` 只影响插值末尾是否自动 HTML 转义：**最外层（最后应用）**过滤器为
`safe-output` 时跳过，否则转义。`x |> safe |> uppercase` 仍会转义。

## 函数（P0 内置）

函数是独立的语言中立命名空间，与过滤器、测试互不重叠。只有**裸标识符调用**
`name(args)` 可以执行，且 `name` 必须命中静态 registry：

| function | 参数 | 规则 |
|----------|------|------|
| `range(start, stop, step=1)` | 2–3 | 仅整数；`step` 为 `0`、非整数参数、结果超过 10000 项 → `null` |
| `min(a, b)` / `max(a, b)` | 2 | 仅有限数字；非数字 → `null`；整数值保持整数形态 |

- 成员调用（`user.format()`）一律拒绝，不派发到宿主。
- 函数是纯函数：不读上下文、不访问宿主、不产生转义 capability。
- 未知函数 → `dejavu.template.unknown-function`；参数个数违约 → `dejavu.template.function-arity`。
- 参数**值**非法不是错误，按值模型规则得到 `null`。

## 测试（P0 内置）

测试是谓词命名空间，语法为 `expr is name`、`expr is not name`、`expr is name(args)`。
`is` 与 `not` 是保留字。

| test | 别名 | 规则 |
|------|------|------|
| `null` | `none` | 值为 `null` |
| `truthy` | — | truthiness 为真 |
| `empty` | — | `""`、`[]`、`{}`；`null` 不算 empty |
| `array` / `object` / `string` / `number` / `boolean` | — | 类型判定，数字不含布尔 |
| `even` / `odd` | — | 仅整数；非整数数字两者都为 `false` |

- `is not` 对最终布尔值取反。
- 未知测试 → `dejavu.template.unknown-test`；参数个数违约 → `dejavu.template.test-arity`。
- 测试同样不读上下文、不渲染输出。

### registry 一致性

`filter`、`function`、`test` 三张表由同一份 Rust 描述导出：
`{"filters":[...],"functions":[...],"tests":[...]}`。Rust JIT、Rust AOT、
TypeScript AOT 与可选宿主都必须按这份描述校验，`pnpm conformance`
的 registry 门逐命名空间对比 Rust dump 与 TS 表。

### 自定义注册（宿主扩展）

宿主可以在渲染调用上追加一组自定义条目，与内置表同构、逐项校验：

```json
{
    "namespace": "filter",
    "name": "shout",
    "aliases": ["loud"],
    "minArgs": 0,
    "maxArgs": 0,
    "capability": "pure"
}
```

- `namespace` 取 `filter` / `function` / `test`，查找顺序与内置一致：内置优先，
  未命中才查自定义；`aliases` 解析到 canonical `name`。
- `minArgs` / `maxArgs` 必填，越界复用既有 arity code（`filter-arity` /
  `function-arity` / `test-arity`），不新增 code。
- `capability` 省略时为 `pure`。`pure` 与内置过滤器一样参与自动转义，
  `safe-output` 仅在最外层过滤器生效（`x |> safe |> uppercase` 仍转义）。
- 与内置条目或彼此重名（含 alias）→ `dejavu.template.registry-conflict`，
  `args` 为 `namespace` / `name`。Rust JIT 在 `host` 阶段报告，AOT 在
  `compile` 阶段报告。
- 被 `RenderOptions.capabilities` 拒绝的能力 → `dejavu.template.capability-not-allowed`，
  `args` 为 `name` / `capability`。

宿主实现失败统一映射为 `dejavu.template.custom-invocation`，
`args` 为 `namespace` / `name` / `message`；实现抛错不得直接穿透渲染栈。
实现必须同步、单次渲染内不可变，且**没有** eval / 源码通道，只能经注册表
声明的名称被调用。成员调用（`user.format()`）仍一律拒绝，不派发到宿主。

| 宿主 | 入口 | 绑定版本 |
|------|------|----------|
| Rust JIT（`dejavu-ir`） | `CustomRegistry` trait（`entries` 与三个调用方法） | — |
| Rust AOT（`dejavu-codegen`） | 注册表编译进产物，运行时经 `invokeCustom` 包装异常 | — |
| TypeScript N-API（`dejavu`） | `renderIr` / `renderSource` 的可选第二参 `registry` | `dejavu.napi/0` |
| WASM（`dejavu-language`） | `renderIr` / `renderSource` 请求对象的 `registry` 字段 | `dejavu.wasm/0` |

JS 注册表形状为 `{ entries, filter?, function?, test? }`：`entries` 是上面的
描述数组，三个命名空间各自把 `name` 映射到实现函数。过滤器与测试接收
`(value, args)`，函数接收 `(args)`。

## 明确不在 v0 内

- 动态宏名（`call <表达式>`）；宏与 caller 块只按静态标识符解析
- 任意宿主方法调用（成员调用不派发，自定义注册只能走裸标识符）
- 带参数的内置 test（内置表全为零参数，宿主注册项可带参数）
- prepend / append 块
- 异步过滤器 / loader
- 上下文敏感转义（attr / url / js / css）
- 单独 `|` 作管道 — 使用 `|>`
- 文件系统 watcher / 实时 FS catalog 后端
- 诊断 `message` 的 locale / i18n（后续版本）

## Conformance

- `specifications/conformance/t1` — 无 loader（含 `safe_raw`）
- `specifications/conformance/values` — truthiness、undefined、运算符、过滤器
- `specifications/conformance/loader` — path-v1 解析
- `specifications/conformance/inheritance` — extends/block/super/include/定界符
- `specifications/conformance/whitespace` — 左右 marker 与五个级别
- `specifications/conformance/include-context` — include 的 `with` / `only` / `without context`
- `specifications/conformance/partial-params` — 参数化 partial 的默认值、全参数与嵌套 include
- `specifications/conformance/functions` — `range` / `min` / `max` 与非法参数
- `specifications/conformance/tests` — `is` / `is not` 谓词
- `specifications/conformance/registry` — 宿主自定义 filter / function / test 分发
- `specifications/conformance/registry/diagnostics` — 注册冲突、自定义 arity 与 capability 拒绝的四宿主一致性
- `specifications/conformance/builtin-expressions` — 解析器到 catalog 到渲染的闭命名空间链路
- 引擎单测 — 夹具之外的边界情况
