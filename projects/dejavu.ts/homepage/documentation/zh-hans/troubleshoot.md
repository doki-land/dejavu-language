# 排查 Dejavu 模板问题

先按可见现象定位，再把模板和上下文缩减到最小失败示例。

## 值渲染成空字符串

缺失标识符默认变成空字符串。检查上下文对象中的拼写和嵌套。开发期间启用 `strictUndefined: true`，把缺失名称转成错误。

## HTML 显示为 `&lt;` 和 `&gt;`

插值默认转义 HTML，这对普通文本和用户控制的文本是预期行为。只有应用已经清洗，或由可信来源生成的 HTML 才能使用 `safe` 或
`raw`。

## 过滤器报错

使用 `|>`，不要使用单独的 `|`。检查内置过滤器名称和参数，支持列表见[过滤器指南](./templates/filters.md)。

## `if` 或 `loop` 无法解析

使用可移植的结束形式：

```dejavu
<% if ready %>Ready<% end if %>
<% loop item in items %><% item %><% end loop %>
```

不要照搬其他模板语言的等号插值或紧凑结束关键字。

## `extends` 或 `include` 找不到模板

- 确认应用已配置 loader。
- 按真实相对路径注册一次模板。
- 使用 `./` 或 `../` 引用时，从具名入口渲染，让 loader 知道当前模板。
- 多个 root 中存在相同路径时，检查优先级或使用显式 scheme。
- 相对路径不能逃逸已配置 root。

## 包导入到了错误的库

安装并导入 `@doki-land/dejavu`。npm 上无作用域的 `dejavu` 是另一个项目。

## 不同宿主的结果不一致

先在两个宿主上渲染相同 IR 和 JSON 上下文，再检查[兼容性页面](./reference/compatibility.md)。规范要求并不能证明每个实现都已经完成该要求。

## 提交可复现问题

附上最小模板、脱敏后的 JSON 上下文、宿主语言与包版本、完整错误或诊断码，以及预期和实际输出。不要附带秘密或生产客户数据。
