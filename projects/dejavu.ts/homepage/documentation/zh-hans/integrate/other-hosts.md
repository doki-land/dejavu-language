# 使用其他宿主绑定

Dejavu 语言和 IR 契约与宿主无关。宿主绑定负责决定应用如何安装库、构造上下文值、加载模板以及呈现诊断。

## 现有实现

仓库包含 TypeScript、Rust、C#、Kotlin 和 Python 的实现或接入工作，但它们的能力覆盖并不相同。不能仅凭目录或包存在就推断功能已可用。

采用绑定前，应检查：

- 它能解析源码，还是只能渲染已有 IR；
- 它运行了哪些 conformance 套件；
- 继承与 loader 解析是否有覆盖；
- `safe` / `raw` 和严格缺失值行为是否经过测试；
- 其公开包是否已在对应生态发布。

当前证据记录在[实现兼容性](../reference/compatibility.md)页面。

## 绑定契约

符合契约的绑定应提供等价操作：

- 把源码解析成 Dejavu IR；
- 使用 JSON 兼容上下文渲染 IR；
- 提供渲染源码的便捷操作；
- 报告解析、路径解析和渲染诊断；
- 启用继承或 include 时加载被引用模板。

框架适配器应调用宿主绑定，不应定义新的模板语法。适配器的路由、请求处理、鉴权和文件发现不属于 Dejavu 语言契约。

绑定缺少能力时，应将其视为实现限制，而不是为该宿主修改模板语言。
