# 文档写作规范

## 一页只解决一个任务

页面开头写读者将完成什么、需要什么、会得到什么。不要先写产品宣言或内部架构。

## 只写有证据的能力

每个能力声明至少链接到 Template Contract、源码测试或 conformance fixture。规划、实验和已交付能力使用不同标题，并明确标注状态。

## 用具体动词

优先使用“运行、创建、传入、注册、检查、修复、比较”。避免没有证据的“强大、完整、统一、高性能、零成本、强类型、编译期、安全无忧”。

## 不混淆读者

用户文档不出现 parser 源码路径、IR 节点内部字段或下游产品名称。核心文档不重复用户教程，也不把实现细节写成语言语义。

## 示例必须可验证

代码块使用公开包、当前定界符和 Contract 中的结束形式。每个重要示例都要写出预期输出或预期诊断。不要使用未纳入 Contract
的语法作为可复制示例。

## 双语同步

英文是用户文档主稿，中文保持相同文件树、标题层级、代码块、包名和输出。翻译可以改变说明文字，但不能改变技术行为或示例。
